# 오늘은 어떤 빵을 먹을까?

> 12개의 선택으로 오늘의 빵 취향을 찾아주는 베이커리 취향 테스트

## 소개

**오늘은 어떤 빵을 먹을까?**는 사용자의 맛, 식감, 풍미, 먹는 방식에 대한 선택을 바탕으로 오늘 가장 잘 맞는 빵을 추천하는 취향 테스트입니다.

성격을 빵에 대응시키는 방식이 아니라 실제 베이커리 선택 기준을 네 가지 축으로 나누고, 12개의 질문 결과를 조합해 16가지 결과 중 하나를 보여줍니다.

## 취향 기준

| 구분 | 선택 A | 선택 B |
| --- | --- | --- |
| 맛 | 달달 | 담백 |
| 식감 | 말랑촉촉 | 씹는맛 |
| 풍미 | 진한 풍미 | 깔끔한 풍미 |
| 구성 | 조합 중심 | 빵 자체 중심 |

각 기준은 3개의 질문으로 판정합니다.

총 12개의 답변을 기준으로 4자리 취향 코드를 생성하고, 해당 코드에 대응하는 결과를 표시합니다.

## 판정 방식

각 취향 축은 3개의 질문으로 구성합니다.

질문과 선택지는 식사 후, 커피 한 모금, 영화 감상, 친구와 나눠 먹기 같은 장면으로 표현합니다. 축 이름이나 재료 목록을 선택지에 직접 나열하지 않고, 빵을 먹을 때의 경험을 고르게 합니다. 상황에 대한 성격이나 생활 계획을 판정에 사용하지 않습니다.

축별로 더 많이 선택된 값을 최종 성향으로 사용합니다.

```text
맛
D D S
→ D

식감
T T M
→ T

풍미
R L R
→ R

구성
B B F
→ B
```

최종 코드:

```text
DTRB
```

결과:

```text
퀸아망
```

각 축이 3문항으로 구성되기 때문에 동점은 발생하지 않습니다.

동일한 응답에는 항상 동일한 결과가 반환됩니다.

## 완료 기준

- 메인 화면에서 테스트를 시작할 수 있음
- 12개의 질문이 모두 정상적으로 표시됨
- 각 질문에서 하나의 답을 선택할 수 있음
- 이전 질문으로 이동할 수 있음
- 답변을 변경하면 결과 계산에 변경값이 반영됨
- 4개의 취향 축이 모두 정상적으로 판정됨
- 가능한 결과 코드가 정확히 16개임
- 각 결과 코드가 하나의 빵 결과와 연결됨
- 동일한 답변에는 동일한 결과가 반환됨
- 16개의 결과가 모두 정상적으로 표시됨
- 결과 설명과 취향 태그가 판정값과 일치함
- 다시 하기를 실행하면 기존 답변이 초기화됨
- 모바일 환경에서 가로 스크롤이 발생하지 않음
- 키보드만으로 테스트를 진행할 수 있음

## 실행

`index.html`을 브라우저에서 열면 사용할 수 있습니다. 패키지 설치, 빌드, 서버 설정이 필요하지 않습니다. Web Share API와 Clipboard API는 브라우저 및 보안 컨텍스트에 따라 지원 여부가 달라집니다. 자동 복사를 사용할 수 없으면 선택 가능한 텍스트 영역을 제공합니다.

공개 URL 공유를 확인하려면 HTTPS 정적 호스팅에서 실행합니다. `file://`로 직접 연 경우 결과 URL 복사 버튼을 숨기고 결과 텍스트만 공유합니다. 컴퓨터 파일 경로는 공유 내용에 포함하지 않습니다. HTTP/HTTPS 접속에서는 결과 링크 공유를 제공하지만, 외부에서 열 수 있는 링크를 만들려면 공개 호스팅 주소가 필요합니다. GitHub Pages의 저장소 하위 경로에서도 동작하도록 스크립트와 이미지에 상대 경로만 사용합니다. 이 작업에서는 배포하지 않았습니다.

## 구현 파일

- `index.html`: 화면, 스타일, 12개 질문, 선택 상태, 다수결 판정, 공유.
- `data/results.js`: 16개 결과의 코드, 이름, 취향 설명, 태그, 기본 빵 소개, 맛 변형 및 활용 4가지, 같이 먹을 빵 2가지와 조합 이유, 먹는 방법, 이미지 경로와 대체 텍스트.
- `assets/images/`: 귀여운 2D 빵 캐릭터로 교체한 메인 이미지와 메뉴별 대표 이미지 16장. 생성 도구와 각 이미지의 실제 프롬프트는 [이미지 제작 기록](./assets/images/README.md)에 정리했습니다.

## 결과 콘텐츠

결과의 취향 설명과 별도로 빵 자체의 재료·모양·식감을 소개합니다. 각 빵에는 맛 변형 또는 활용법 4가지가 있습니다. 예를 들어 스콘에는 플레인·얼그레이·유자·앙버터 스콘 각각의 차이를 설명합니다. 변형 메뉴는 기본 빵과 단맛·필링 등이 달라질 수 있으며, 16개 기본 결과의 판정은 그대로 유지합니다.

같이 먹으면 좋은 빵은 각 결과에 2개씩 제공하며, 단맛과 담백함 또는 서로 다른 식감을 번갈아 즐기도록 구성한 편집 추천입니다. 두 개의 정보 카드를 나란히 표시하고 이름·캐릭터 이미지·조합 이유만 제공합니다. 추천 카드는 클릭하거나 키보드로 활성화할 수 없으며, 다른 결과로 이동하는 링크가 없습니다. 별도 추천 API나 확률 계산은 사용하지 않습니다.

스콘의 과일·초콜릿·향신료 등 변형은 [King Arthur Baking의 스콘 레시피 모음](https://www.kingarthurbaking.com/recipes/scones?menu%5Bcategory_lvl0%5D%5B0%5D=Scones)을, 페이스트리의 샌드위치 활용은 [파리바게뜨의 런치샌드위치 소개](https://www.paris.co.kr/product/new-lunch-sandwich/)를 참고했습니다. 함께 먹을 빵 조합과 이유는 이 서비스에서 작성했습니다.

## 모바일 적용

노치와 홈 인디케이터 주변 여백, 작은 화면에서 첫 화면 안에 보이는 시작 버튼, 한 열로 읽는 맛 변형 목록, 48px 이상의 터치 영역을 적용했습니다. 가로 화면에서는 질문 여백을 줄이고, 스크롤해도 진행률이 상단에 유지됩니다. 터치 기기에는 마우스용 hover 강조를 적용하지 않습니다. 이미지 전체가 보이도록 `contain`으로 표시하며, 입력 영역은 iOS의 자동 확대를 줄이도록 16px 글자 크기를 사용합니다.
